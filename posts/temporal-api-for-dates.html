Handling dates and times with the Temporal API

JavaScript · No dependencies required

For years, working with dates in JavaScript meant reaching for a library such as Moment.js, date-fns or Luxon, because the built-in Date object is mutable, has a confusing API and doesn't understand time zones well. Temporal is a new, standards-track API designed to fix exactly that — and you can use it without adding a single dependency.

Why Temporal instead of a library

  • Objects are immutable — every operation returns a new instance.
  • Separate types for separate concerns: Temporal.PlainDate, Temporal.PlainTime, Temporal.ZonedDateTime, Temporal.Duration, and more.
  • Time zones and calendars are first-class, instead of being bolted on.
  • No months-are-zero-indexed surprises, and comparisons are explicit and unambiguous.

Basic usage

// A calendar date, with no time or time zone attached.
const date = Temporal.PlainDate.from('2024-03-01');

// Add a duration and get a brand-new PlainDate back.
const nextMonth = date.add({ months: 1 });

// Time-zone aware "now", ready for formatting or comparisons.
const now = Temporal.Now.zonedDateTimeISO();

console.log(date.toString());      // 2024-03-01
console.log(nextMonth.toString()); // 2024-04-01
console.log(now.toString());       // e.g. 2024-03-01T12:34:56.789+01:00[Europe/Oslo]

Comparing two dates

const a = Temporal.PlainDate.from('2024-01-01');
const b = Temporal.PlainDate.from('2024-06-15');

Temporal.PlainDate.compare(a, b); // -1 (a is before b)
a.until(b).toString();            // 'P166D' — a Temporal.Duration
